# Super Metroid Map Rando for Archipelago

> **Credit and scope**: this project is built on [lordlou's Map Rando Archipelago world](https://github.com/MultiworldGG/MultiworldGG/tree/main/worlds/sm_map_rando)
> and lordlou's [SMBasepatch](https://github.com/lordlou/SMBasepatch). lordlou's world is the established Map Rando
> Archipelago world; this repository is **not** meant to replace it. It started as an experiment: to see whether the
> world could track upstream Map Rando automatically and expose every maprando.com setting and preset as options.
> If you just want to play Map Rando in Archipelago, use lordlou's version.

An experimental Archipelago world (`sm_map_rando.apworld`) for [Super Metroid Map Rando](https://maprando.com). It
uses Map Rando v123 (lordlou's world uses v119) and exposes all the settings and presets of the maprando.com website as
Archipelago options.

**Download**: see [Releases](https://github.com/JimLundin/sm-map-rando-archipelago/releases):

- `sm_map_rando.apworld`: the world (includes the native randomizer for Windows x86-64, Linux x86-64/aarch64 and
  macOS).
- `Super Metroid Map Rando.yaml`: a template with every option and its documentation.

You need your own Super Metroid (JU) ROM; none is included or distributed.

Player-facing documentation is in `worlds/sm_map_rando/docs/`.

## How it works

- **Randomizer**: the upstream Map Rando Rust code, compiled as a Python extension (`native/pysmmaprando`, a thin
  JSON-based binding). The `MapRandomizer` submodule is upstream [blkerby/MapRandomizer](https://github.com/blkerby/MapRandomizer)
  at a pinned commit, with the small changes in `patches/` applied (a configurable data directory, and an optional item
  PLM override so that Map Rando's patcher uses the Archipelago item PLMs). Map pools are downloaded on demand (and
  cached), as are Samus sprites and Mosaic tile patches when patching.
- **Options** (`worlds/sm_map_rando/Options.py`) are generated by `tools/gen_options.py` from Map Rando itself: the
  settings structure and enum values from `settings.rs` (`tools/rust_schema.py`), the presets as loaded by Map Rando
  (through the native module), and labels/help texts extracted from the website templates (`tools/catalog/`). Settings
  are built in layers like on the website (settings preset → category presets → group presets → individual settings),
  then preset names are recomputed (`settings_builder.py`). New upstream settings get options automatically.
- **Upstream checks**: `tools/upstream_checks.py` fingerprints the few pieces of upstream code that are mirrored by hand
  (presets only defined in the website's JavaScript, the Customize form mapping, Mosaic themes, ...), and tests check
  the world against Map Rando's data (items, group presets).
- **Logic**: derived from Map Rando's item placement steps: a step's locations require all items from earlier steps
  (sound by construction, since Map Rando's own placement satisfies it). Steps with fewer than 5 locations
  (bottlenecks) keep their items local (`local_early_progression`) to make multiworld fills reliable.
- **ROM**: the Map Rando patcher builds the ROM, using the AP item PLMs for all item locations; then the Archipelago
  multiworld basepatch and tables are applied. The basepatch (`basepatch/`, from lordlou's
  [SMBasepatch](https://github.com/lordlou/SMBasepatch), MIT) is relocated to free space in Map Rando's ROM layout and
  extended with Spark Booster and Blue Booster; `tools/build_basepatch.py` assembles it and checks it doesn't overlap
  Map Rando's patches.

## Repository layout

- `worlds/sm_map_rando`: the Archipelago world.
- `native/pysmmaprando`: the Python bindings to Map Rando (Rust).
- `patches/`: changes applied to the MapRandomizer submodule.
- `basepatch/`: the Archipelago multiworld basepatch (65816 assembly).
- `tools/`: build scripts, options generator, upstream checks, headless emulator test harness (`tools/emu.py`).
- `MapRandomizer` (submodule): upstream Map Rando.

## Building

Requirements: Python 3.11+ with `maturin`, Rust, CMake and a C++ compiler (for the asar assembler).

```
git clone --recursive https://github.com/JimLundin/sm-map-rando-archipelago.git && cd sm-map-rando-archipelago
python tools/prepare_upstream.py                   # submodules, patches, version files
(cd native/pysmmaprando && maturin build --release --strip -o ../../dist/wheels)
pip install dist/wheels/pysmmaprando-*.whl
python tools/build_apworld.py                      # data, options, basepatch, tables -> dist/sm_map_rando.apworld
```

`tools/build_apworld.py` bundles all wheels found in `dist/wheels` (CI builds them for Windows, Linux and macOS).

## Updates and releases

- **CI** (`.github/workflows/build.yml`): every push and pull request builds the wheels for Windows x86-64, Linux
  x86-64/aarch64 and macOS (universal2), assembles the `.apworld`, runs the tests in Archipelago and generates the
  options template.
- **Upstream updates** (`upstream.yml`): weekly, if Map Rando's `main` moved, the submodule is updated, everything is
  regenerated, and a pull request is opened with a report (patches that no longer apply, build errors, new settings,
  changed upstream code to review).
- **Releases** (`release.yml`): pushing a `v*` tag builds everything and publishes the `.apworld` and the template.
  Before tagging, run the ROM integration test locally (it needs a ROM, which can't be used in CI):
  `SMMR_TEST_ROM=/path/to/rom.sfc python -m pytest worlds/sm_map_rando/test/test_rom_integration.py`.
  The world version is `0.<Map Rando version>.<WORLD_REVISION>`.

## Testing

Link or copy `worlds/sm_map_rando` into an Archipelago checkout's `worlds/` and run
`python -m pytest worlds/sm_map_rando/test`. The tests cover settings building (all presets round-trip through Map
Rando's own settings validation), consistency with Map Rando's data, generation with many setting combinations,
shared maps, and the Archipelago ROM tables; with `SMMR_TEST_ROM` set, also building a ROM and checking every item PLM
in every room state.

## Status / known limitations

- Tested with a real Super Metroid (JU) ROM in a headless emulator (snes9x libretro core driven by `tools/emu.py`):
  the patched ROM boots into gameplay; items sent through the receive queue (as the SNI client does) are received,
  including Wall Jump Boots, Spark Booster and Blue Booster and custom pickup sizes; picking up own items and other
  players' items works, with the right message boxes ("YOU FOUND TOY SHOVEL FOR HIKE"). Not yet played through
  with a real SNI client connection.
- With several Map Rando worlds in one multiworld, generation can occasionally fail during fill (none in the latest
  test runs with `local_early_progression`); regenerating with another seed works.
- Native module bundled for Windows x86-64, Linux x86-64/aarch64 and macOS (universal2); other platforms need to build
  it (see the setup guide). The macOS and Linux aarch64 builds are built and tested by CI but haven't been tried by a
  player yet.
- Item fanfares: items in the ROM use the Archipelago item PLMs, which play a sound effect rather than the fanfare,
  regardless of the `fanfares` setting.
- Some combinations of settings are too restrictive for Map Rando (e.g. Basic skill assumptions with collectible wall
  jump or beam doors and the ship start); generation reports an error for these.

The ROM integration test runs when `SMMR_TEST_ROM` is set to the path of a Super Metroid (JU) ROM.
