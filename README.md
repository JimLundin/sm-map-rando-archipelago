# Super Metroid Map Rando for Archipelago

An Archipelago world (`sm_map_rando.apworld`) for [Super Metroid Map Rando](https://maprando.com), based on Map Rando
v123, exposing all the settings and presets of the maprando.com website as Archipelago options.

This is a continuation of [lordlou's Map Rando Archipelago world](https://github.com/MultiworldGG/MultiworldGG/tree/main/worlds/sm_map_rando)
(Map Rando v119), updated to Map Rando v123 and extended to expose every maprando.com setting and preset.

**Download**: see [Releases](https://github.com/JimLundin/sm-map-rando-archipelago/releases):

- `sm_map_rando.apworld`: the world (includes the native randomizer for Windows x86-64 and Linux x86-64).
- `Super Metroid Map Rando.yaml`: a template with every option and its documentation.

You need your own Super Metroid (JU) ROM; none is included or distributed.

Player-facing documentation is in `worlds/sm_map_rando/docs/`.

## How it works

- **Randomizer**: the upstream Map Rando Rust code, compiled as a Python extension (`pysmmaprando`). The bindings are a
  new crate, `MapRandomizer/rust/pysmmaprando` (branch `ap-integration` of a MapRandomizer checkout); the only changes
  to upstream code are a configurable data directory (`maprando::paths`) and an optional item PLM override. Map pools are downloaded on demand (and
  cached), as are Samus sprites and Mosaic tile theme patches when patching.
- **Options** (`worlds/sm_map_rando/Options.py`) are generated by `tools/gen_options.py` from the website's settings,
  labels and help texts (`tools/settings_catalog.json`, extracted from the website templates). Settings are built in
  layers like on the website: settings preset → category presets → group presets (enhanced map, crash fixes, ...) →
  individual settings, then preset names are recomputed (`settings_builder.py`). Settings JSON exported from
  maprando.com can be used directly (`map_rando_settings`).
- **Logic**: derived from Map Rando's item placement steps: a step's locations require all items from earlier steps
  (sound by construction, since Map Rando's own placement satisfies it). Steps with fewer than 5 locations
  (bottlenecks) keep their items local (`local_early_progression`) to make multiworld fills reliable.
- **ROM**: the Map Rando patcher builds the ROM, using the AP item PLMs for all item locations (an optional override
  added to Map Rando's patcher, so that items Map Rando copies between room states get them too); then the
  Archipelago multiworld basepatch and tables are applied. The basepatch (`SMBasepatch`, branch `maprando-v123`, `romhacks/maprando`) is
  lordlou's SM multiworld basepatch, relocated to free space in the v123 ROM layout and extended with Spark Booster and
  Blue Booster. It hooks Map Rando's `LoadGame` (saveload.asm) to keep the item receive queue consistent with saves.

## Repository layout

- `worlds/sm_map_rando`: the Archipelago world.
- `tools/`: options generator (and the website settings catalog it uses), apworld build script, IPS tools, headless
  emulator test harness.
- `MapRandomizer` (submodule, [JimLundin/MapRandomizer](https://github.com/JimLundin/MapRandomizer), branch
  `ap-integration`): upstream Map Rando plus the `pysmmaprando` Python bindings.
- `SMBasepatch` (submodule, [JimLundin/SMBasepatch](https://github.com/JimLundin/SMBasepatch), branch `maprando-v123`):
  the Archipelago multiworld basepatch, Map Rando v123 variant in `romhacks/maprando`.

Clone with `git clone --recursive`, or run `git submodule update --init --recursive` after cloning.

## Building

Requirements: Rust, Python 3.11+ with `maturin` (and `ziglang` for the Windows cross-build), the Archipelago sources.

```
# Native module (wheels into dist/wheels)
cd MapRandomizer/rust/pysmmaprando
maturin build --release --strip -o ../../../dist/wheels
maturin build --release --strip --target x86_64-pc-windows-gnu --zig -o ../../../dist/wheels

# AP basepatch (needs asar: tools/bin/asar, built from MapRandomizer/asar)
cd SMBasepatch && ASAR=../tools/bin/asar bash build.sh

# Options, data and the .apworld
python tools/gen_options.py
python tools/build_apworld.py
```

## Testing

Link or copy `worlds/sm_map_rando` into an Archipelago checkout's `worlds/` and run
`python -m pytest worlds/sm_map_rando/test`. The tests cover settings building (all presets round-trip through Map
Rando's own settings validation), generation with many setting combinations, shared maps, and the Archipelago ROM
tables, and (with `SMMR_TEST_ROM` set) building a ROM and checking every item PLM in every room state.

## Status / known limitations

- Tested with a real Super Metroid (JU) ROM in a headless emulator (snes9x libretro core driven by `tools/emu.py`):
  the patched ROM boots into gameplay; items sent through the receive queue (as the SNI client does) are received,
  including Wall Jump Boots, Spark Booster and Blue Booster and custom pickup sizes; picking up own items and other
  players' items works, with the right message boxes ("YOU FOUND TOY SHOVEL FOR HIKE"). Not yet played through
  with a real SNI client connection.
- With several Map Rando worlds in one multiworld, generation can occasionally fail during fill (none in the latest
  test runs with `local_early_progression`); regenerating with another seed works.
- Native module bundled for Windows x86-64 and Linux x86-64 only; other platforms need to build it (see the setup
  guide).
- Item fanfares: items in the ROM use the Archipelago item PLMs, which play a sound effect rather than the fanfare,
  regardless of the `fanfares` setting.
- Some combinations of settings are too restrictive for Map Rando (e.g. Basic skill assumptions with collectible wall
  jump or beam doors and the ship start); generation reports an error for these.

The ROM integration test runs when `SMMR_TEST_ROM` is set to the path of a Super Metroid (JU) ROM.
